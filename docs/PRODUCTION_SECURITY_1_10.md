# EdNotebook production security layers 1–10

This runbook documents the production-security pipeline for educational files, previews, subscriptions, publication entitlements, and external links.

The implementation is deliberately **fail-closed**: a browser upload never becomes a learner-accessible file merely because the bytes reached object storage. Availability is granted only after the security worker reports a clean verdict and any archive inspection succeeds.

## Current deployment boundary

The Supabase schema and Edge Functions are deployed to project `didwxihufueqbpfnfdmm`.

Deployed Edge Functions:

- `secure-upload-session`
- `secure-upload-complete`
- `secure-worker-callback`
- `secure-file-download`
- `secure-file-delete`
- `retention-worker`
- `stripe-webhook`
- `link-preview`

The containerized document-security worker is versioned in `services/document-security-worker/`. It must be deployed to an always-on container host with ClamAV, LibreOffice, and Poppler available. Until its URL and shared token are configured as Supabase Edge secrets, uploaded files remain quarantined/manual-review and cannot be downloaded through the application.

## 1. Malware scanning and quarantine

### Storage path

Every browser cloud upload is reserved through `secure-upload-session` and sent only to the private `ed-quarantine` bucket.

The final private destination is recorded in `secure_file_objects` but is not written until the worker reports a clean result.

### Security states

Typical state progression:

```text
reserved → uploading → uploaded → scanning → clean → released
```

Failure states include:

```text
infected
suspicious
manual_review
error
blocked
deleted
```

A file is downloadable only when:

```text
security_status = clean
availability_status = released
```

### Scanner

The worker uses ClamAV and records:

- scanner provider
- engine version
- signature version
- detected MIME type
- SHA-256 checksum
- byte count
- scan details and verdict

The worker callback is authenticated by a per-file random callback token. Only the token hash is stored in Postgres.

## 2. Resumable TUS uploads

The frontend uses `tus-js-client` and uploads directly to the project Storage TUS endpoint:

```text
https://didwxihufueqbpfnfdmm.storage.supabase.co/storage/v1/upload/resumable
```

The upload reservation returns:

- secure file ID
- quarantine bucket and path
- signed upload token
- upload expiry
- plan quota and maximum file size
- retention date

TUS requests use the signed token in `x-signature` and use 6 MiB chunks. Interrupted uploads can resume while the reservation remains valid.

After TUS reports success, the browser calls `secure-upload-complete`. That endpoint verifies that the quarantine object exists and that its byte count matches the reservation before dispatching security processing.

---

## 3. ZIP and archive inspection

Archive inspection occurs after malware scanning and before release.

The worker rejects or blocks archives containing:

- `../` traversal or absolute paths
- symbolic links, devices, or unsupported special entries
- encrypted members
- executable or active-content payloads
- Office macro content
- excessive entry count
- excessive uncompressed size
- suspicious compression ratio
- excessive nested archive depth

Default worker limits:

```text
maximum entries: 5,000
maximum expanded bytes: 250 MiB
maximum compression ratio: 100:1
maximum nested depth: 2
```

Archive failure keeps the source in quarantine and sets availability to `blocked`.

---

## 4. Server-generated previews

Previews are generated by the container worker, not by opening untrusted office or publication files in the user’s browser.

Supported preview paths include:

- image thumbnail
- PDF page images/text
- Word document rendering through LibreOffice
- PowerPoint slide rendering through LibreOffice
- EPUB cover/text extraction
- text/Markdown preview
- JSON metadata preview

Preview objects are stored in the private `ed-previews` bucket and indexed in `file_previews`.

The browser requests a short-lived preview delivery URL through `secure-file-download`, which performs the same file-access check and records an audit event.

The callback payload is bounded to 24 previews, 5 MiB per preview, and 8 MiB total callback preview bytes.

---

## 5. Audit events

`audit_events` records security-sensitive activity, including:

- upload reservation
- upload completion
- scanner dispatch
- scanner failure
- malware block
- archive block
- file release
- file or preview download
- rename/share/delete actions
- retention deletion
- upload expiry
- Stripe webhook processing
- link-preview retrieval

Request IP address and user agent are stored only as salted hashes. Audit rows include user, institution, course, assignment, file/resource, target, request ID, event type, timestamp, and structured details.

Application downloads must use `secure-file-download`; directly generating Storage download URLs in the public client would bypass the audit and release checks.

---

## 6. Retention and legal holds

Retention can be defined at institution and course scope through `retention_policies`.

Each secure file receives a calculated `retention_until` value at upload reservation. Deletion requests pass through `request_secure_file_deletion` and can be:

- immediately eligible
- deferred until retention expires
- blocked by an active legal hold
- processed
- completed
- failed

`legal_holds` can apply to an institution, course, or specific file through `legal_hold_files`.

The `retention-worker` Edge Function processes eligible deletions and expired upload reservations. It requires the `x-cron-secret` header and should be invoked daily by the GitHub Actions retention schedule.

A legal hold always wins over an ordinary deletion or retention expiry.

---

## 7. Storage quotas by subscription tier

Quota reservations are atomic and occur before a signed upload token is issued.

Current launch limits:

| Tier | Total storage | Maximum file | Default retention |
|---|---:|---:|---:|
| Free | 250 MiB | 25 MiB | 30 days |
| Starter | 2 GiB | 100 MiB | 365 days |
| Professor | 10 GiB | 250 MiB | 730 days |
| Institution | 100 GiB | 500 MiB | 2,555 days |
| Enterprise | 1 TiB | 500 MiB | 3,650 days |

`get_my_storage_usage` returns plan, used bytes, reserved bytes, remaining bytes, quota, and maximum file size.

A quota reservation changes from `reserved` to `committed`, `released`, or `expired`. Deleted files release their committed storage from usage calculations.

The plan table is the source of truth; frontend labels must not be treated as authorization.

## 8. Stripe webhook verification and entitlements

Stripe webhook endpoint:

```text
https://didwxihufueqbpfnfdmm.supabase.co/functions/v1/stripe-webhook
```

The endpoint:

- reads the raw request body
- verifies `Stripe-Signature`
- rejects missing Edge secrets
- stores Stripe event IDs for idempotency
- maps customers to Supabase users
- maps subscription prices to EdNotebook plans
- updates subscription status
- creates purchase/rental publication entitlements
- synchronizes Stripe Entitlements features when available
- records billing audit events

Subscribe the Stripe endpoint to:

```text
checkout.session.completed
customer.subscription.created
customer.subscription.updated
customer.subscription.deleted
customer.subscription.paused
customer.subscription.resumed
invoice.paid
invoice.payment_failed
entitlements.active_entitlement_summary.updated
```

A browser return from Stripe Checkout never grants access by itself. Access is created only after a verified webhook.

Populate `stripe_price_plan_map` or configure the four price-ID Edge secrets before accepting subscriptions.

## 9. EduBook conversion worker

The containerized worker is located at:

```text
services/document-security-worker/
```

Processing order:

1. download the short-lived quarantine URL
2. confirm byte count and SHA-256
3. identify the real file type
4. scan with ClamAV
5. inspect archives and office packages
6. generate bounded previews
7. extract machine-readable text and structure
8. create an `EduBook/1.0` draft for requested publications
9. return results through the per-file callback token
10. let the Edge callback release or block the object

Supported conversion inputs include PDF, DOCX, PPTX, EPUB, text, Markdown, and supported archive/package sources.

An LLM may propose knowledge checks, vocabulary, discussion, or instructional scaffolds after extraction, but it must not be the sole source of the publication text.

### Worker environment

Required:

```text
EDNOTEBOOK_WORKER_TOKEN
MAX_DOWNLOAD_BYTES
CLAMAV_HOST or local clamd socket/configuration
```

The same token value is configured in Supabase as `DOCUMENT_SECURITY_WORKER_TOKEN`.

Health and processing endpoints are defined in the worker FastAPI application. Do not expose the processing endpoint without bearer-token protection and platform-level TLS.

## 10. Server-side Open Graph previews

`link-preview` receives an authenticated URL request and fetches the remote page from the server.

Security controls include:

- HTTP/HTTPS only
- no embedded credentials
- standard ports only
- localhost/private/reserved network blocking
- DNS A/AAAA validation before every request
- redirect revalidation, maximum five redirects
- nine-second fetch timeout
- one-megabyte response limit
- HTML/text content-type allowlist
- sanitized title, description, site name, canonical URL, image URL, and favicon URL
- 24-hour successful cache
- short error cache
- audited retrieval

The endpoint blocks common SSRF paths, including loopback, link-local, RFC1918, carrier-grade NAT, documentation/test ranges, unique-local IPv6, and multicast/reserved networks.

Remote image/favicon URLs are metadata only. Production UI should avoid silently fetching them from a third party unless the learner or professor expects that connection; a future image-proxy cache can place those bytes behind the same bounded fetch and private/public delivery policy.

# Supabase Edge secrets

Repository/GitHub secrets do not automatically become Supabase Edge Function secrets. Configure these in the Supabase dashboard or CLI:

```text
ALLOWED_ORIGINS
AUDIT_HASH_SALT
DOCUMENT_SECURITY_WORKER_URL
DOCUMENT_SECURITY_WORKER_TOKEN
RETENTION_CRON_SECRET
STRIPE_SECRET_KEY
STRIPE_WEBHOOK_SECRET
STRIPE_PRICE_STARTER
STRIPE_PRICE_PROFESSOR
STRIPE_PRICE_INSTITUTION
STRIPE_PRICE_ENTERPRISE
```

Recommended `ALLOWED_ORIGINS` while GitHub Pages is the live domain:

```text
https://brexatlas.github.io,http://localhost:5173,http://127.0.0.1:5173
```

Add the exact custom EdNotebook domain after DNS/Pages cutover.

Generate independent high-entropy values for:

```text
AUDIT_HASH_SALT
DOCUMENT_SECURITY_WORKER_TOKEN
RETENTION_CRON_SECRET
```

Never use a Stripe secret, service-role key, worker token, or cron secret in a `VITE_*` environment variable.

# GitHub Actions secrets

The scheduled retention workflow requires:

```text
RETENTION_CRON_SECRET
```

It must exactly match the Supabase Edge secret.

The document-worker image workflow publishes to GitHub Container Registry using the workflow’s built-in `GITHUB_TOKEN`; no separate registry password is required unless deployment automation pulls into a restricted external platform.

# Production smoke tests

- Unauthenticated calls to JWT-protected functions return 401.
- Worker callback without a valid per-file token returns 401.
- Retention worker without the cron secret returns 401.
- Stripe webhook with an invalid signature is rejected.
- A safe file stays quarantined until worker callback.
- A clean file releases to the final private bucket and becomes downloadable through a short-lived audited URL.
- An infected or suspicious file never reaches the final bucket.
- A held file cannot be deleted.
- A retained file is deferred until its eligibility date.
- A user above quota cannot reserve an upload.
- Duplicate Stripe events do not create duplicate entitlements.
- Private/link-local URLs are rejected by the Open Graph service.

# Remaining account-level Supabase setting

Enable leaked-password protection in Supabase Auth when the project plan supports it. The production-security database schema has no unresolved security-advisor findings beyond that account-authentication setting.
