# EdNotebook Feature Activation Roadmap

**Purpose:** Present the full EdNotebook feature set in everyday language while controlling which capabilities are visible during each stage of the product.

**Status rule:** Repository presence does not automatically mean production readiness. Every public status must be confirmed through end-to-end testing.

Use four statuses:

- **Ready to demonstrate now** — a real user can complete the primary path today in the current environment.
- **Built in part and being connected** — meaningful work exists, but the complete journey, data connection, reliability, or user experience is not finished.
- **Preserved but hidden until later** — the feature should remain in the project but should not appear in the first-user experience until tested and supported.
- **Planned after proof and partnerships** — the direction is defined, but activation depends on adoption evidence, credentials, contracts, or institutional readiness.

The technical or internal term appears in parentheses after the user-facing explanation.

- **Generate and review a course map before students see it** (Course Forge / course-generation workflow)
- **Preview parts of the course as a learner** (Learner preview)
- **Create assignments and write instructions** (Assignment builder)
- **Create custom grading criteria and point values** (Rubric builder)
- **Draft a syllabus section from an assignment** (Syllabus-section generator)
- **Attach documents, images, books, slide decks, audio, video, spreadsheets, and ZIP files** (Materials Studio)
- **Attach public links and YouTube videos inside course areas** (External resource panels and YouTube embed)
- **Add quotations with source and attribution information** (Quote resource records)
- **Build tables for course use and download them as CSV** (Table Builder)
- **Build concept maps** (Concept Map tool)
- **Use a scientific calculator** (Scientific Calculator)
- **Generate subject-specific practice or teaching material** (Subject Generator)
- **Create and edit a presentation deck inside the platform** (EdSlides/1.0 Slide Studio)
- **Read interactive books with chapter navigation, notes, highlights, questions, and bookmarks** (Interactive Reader / EduBook)
- **Create an interactive book immediately from text or Markdown** (Text-to-EduBook conversion)
- **Apply to become a publisher or supplier** (Publisher application)
- **Use a cloud course room for course messages** (Learning Messages / Supabase Realtime course room)
- **Keep temporary private notes on the current device** (Device Notebook)

## Built in part and being connected

- **Save the entire professor journey reliably across sessions and devices** (Course persistence and connected portal workflow)
- **Turn uploaded syllabi into confirmed calendars, assignments, and exam dates** (Syllabus extraction and calendar connection)
- **Send announcements that are saved, delivered, edited, and measured** (Professor Announcements)
- **See which students opened or acknowledged an announcement** (Announcement delivery and read metrics)
- **Manage course conversations with replies, edits, reports, unread counts, and message deletion choices** (Unified Message Center)
- **Review uploaded student files only after they pass security checks** (Secure assignment attachment review)
- **Connect assignments, questions, rubrics, and student work to learning outcomes** (Outcome Evidence Matrix)
- **See student progress, streaks, risk indicators, and mastery summaries from real data** (Professor analytics and roster intelligence)
- **Approve AI-assisted grading suggestions instead of posting them automatically** (Professor-controlled grading review)
- **Offer office-hour appointment slots that students can book** (Office Hours Scheduler)
- **Create shared assignment spaces where permitted** (Collaborative Shared Spaces)
- **Import and export course packages and assessments** (Common Cartridge and QTI adapters)
- **Connect EdNotebook beside an institution’s existing learning system** (LTI 1.3 / LTI Advantage)
- **Receive course rosters and exchange grades with approved systems** (OneRoster 1.2)
- **Award portable achievements** (Open Badges)

## Preserved but hidden until later

- **Use advanced course-wide evidence reports before enough real data exists** (Evidence Studio advanced reports)
- **Run detailed student-integrity reviews before policy, appeal, and false-positive testing are complete** (Learning Integrity signals)
- **Use writing-style comparisons before consent and reliability requirements are complete** (Authorship Continuity Profile)
- **Publish paid books and collect royalties before seller, tax, refund, and rights systems are complete** (Marketplace and Stripe Connect)

# 11. Recommended first public release

The first controlled public release should emphasize only these visible journeys:

## Professor

1. Create an account.
2. Create a course.
3. Upload or paste a syllabus.
4. Review the extracted course structure and dates.
5. Add an assignment and rubric.
6. Add course materials.
7. Preview the learner experience.
8. Invite a small student group.
9. Send an announcement or course message.
10. Review basic use and feedback.

## Student

1. Upload a syllabus or join a course.
2. See what is due next.
3. Open assignments and materials.
4. Receive announcements.
5. Ask course or assignment questions.
6. Submit work.
7. Use interactive reading and notes.
8. Provide feedback.

## Institution or pilot sponsor

1. Review security, privacy, accessibility, and data-use documentation.
2. Define the pilot population and goals.
3. Verify role and course separation.
4. Review support and incident procedures.
5. Receive a basic pilot report.

Everything else should be preserved behind feature flags until the core journeys are stable.

# 12. Activation governance

A feature may move from hidden to visible only when:

1. The user journey is complete.
2. The required data is saved correctly.
3. Access rules are tested.
4. Error and recovery states exist.
5. Mobile behavior is acceptable.
6. Accessibility has been checked.
7. Security and privacy effects are understood.
8. Support documentation exists.
9. The feature supports professor adoption, student return, institutional trust, or outcome improvement.
10. A named person owns the feature after launch.

The Owner may accelerate or delay a feature, but the reason and activation evidence should be recorded.
